# ESS 운영계획·비용 평가 (v1)

담당: 최적화·대시보드팀.
구현: `src/vpp/optimization.py`(`EssParams`, `solve_window`, `run_rolling`),
`src/vpp/baselines.py`, `src/vpp/evaluation.py:summarize_backtest`, `src/vpp/validation.py`,
`src/vpp/portfolio_data.py`, CLI `python -m vpp.backtest`. 가정값은 `config/ess_v0.yaml`.
`schemas.py`의 `OptimizationRequest`/`OptimizationResult`는 아직 빈 틀이며 `plan_ess`는 스키마 합의 후
`run_rolling`에 연결한다.

**결과 해석 주의**: v0는 실측 하루전 SMP와 실측 발전량을 그대로 넣는 **완전예측 백테스트**다.
실제 입찰 성과가 아니며, REC·실시간 정산·입찰 편차 페널티는 범위 밖이다.

## 2. 수식

변수(시간 t, 단위 MWh): 판매 `q`, 충전 `c`, 방전 `d`, 자발 감축 `r`, 구간 끝 에너지 `E`, 충전모드 `z ∈ {0,1}`
파라미터: 발전 `G[t]` (MWh), 하루전 가격 `p[t]` (원/MWh), 구간 길이 `dt[t]` (h), 열화비 `k` (원/MWh),
REC 가산 `ρ[t] = w · P_REC[월(t)]` (원/MWh, 가중치 `w` × REC 단가, `--rec` 없으면 0)

```
max  Σ_t (p[t] + ρ[t])·q[t]  −  k · Σ_t (c[t] + d[t])

G[t] + d[t] = q[t] + c[t] + r[t]                  전력균형 (계통 충전 금지)
E[t] = E[t−1] + η_c·c[t] − d[t]/η_d               SOC 전이, E[−1] = 시작 에너지
SOC_min·Cap ≤ E[t] ≤ SOC_max·Cap
0 ≤ c[t] ≤ min(G[t], P_ch·dt[t]),  c[t] ≤ P_ch·dt[t]·z[t]
0 ≤ d[t] ≤ P_dis·dt[t]·(1 − z[t])                 동시 충방전 금지
q[t] ≥ 0,  0 ≤ r[t] ≤ G[t]
q[t] ≤ C[t]·dt[t]   (선택, 기본 C[t] = ∞ → 제약 없음)
E[마지막] ≥ E_min_final, ≤ E_max_final             (선택, §3 종료 정책)
```

- 에너지 변수이므로 수익 식에 `dt`를 다시 곱하지 않는다. 4 MW는 1시간에 최대 4 MWh.
- 음수·0 가격은 실제 값이며 그대로 둔다 (감축 `r`로 대응). REC 가 있으면 `p + ρ ≥ 0` 인 시간은
  음수 SMP 라도 판매가 유리할 수 있다.
- `no_ess_same_curtailment_policy_krw = Σ max(p+ρ,0)·G` 를 비교용으로 함께 계산한다. 목적함수와의
  차이가 그 구간의 **ESS 없음 대비 추가수익**이다.
- REC (`src/vpp/rec.py`, `config/rec_v0.yaml`, `status: experiment_assumption_not_contract`):
  판매 시점에 1회만 붙인다 (충전분에는 안 붙고 방전 판매분에 붙으므로 저장을 거친 전력은 왕복 손실만큼
  REC 도 준다). 포트폴리오 단일 가중치, 단가는 월별 표 또는 단일 시나리오 값. 집계에서는
  `sales_revenue_krw`(SMP 분)와 `rec_revenue_krw`(가산 분)를 나눠 적고
  `objective_krw = sales + rec − 열화비`. ESS 없음·규칙 기준도 같은 `p + ρ` 로 판매/감축을 정한다
  (MILP 에만 REC 를 더하면 ESS 추가수익이 부풀려진다). **시작 저장분이 팔릴 때도 REC 가 붙는다**
  (전력 출처 추적 없음, 제외는 미구현). 대신 보수적 상한 `initial_energy_rec_upper_bound_krw`
  (실제 시작 잔량 × 방전 효율 × 기간 최고 가산)를 요약에 따로 적는다. 실제 발급 기준(발전기 계량 vs
  송전량)·계약 형태(고정가격 vs 현물)·ESS 연계 가중치는 확인 후 교체.
- `terminal_constraint_cost_krw` 는 마지막 창의 종료 제약을 풀었을 때 늘어나는 계산상 수익이다 (같은
  창을 제약 없이 한 번 더 풀어 뺀 값, 구간마다 한 번). 충·방전이 없어도 남겨 둔 잔량을 못 판 기회비용이
  들어가므로 실제 충전 비용이 아니고, 순수익에 더해 사이클 수익으로 읽으면 안 된다. 계획에는 영향을
  주지 않는 참고 지표다.

## 3. 풀이 방식 (`run_rolling`, `policy`)

| policy             | 창                 | 확정        | 종료 제약                                                 |
| ------------------ | ------------------ | ----------- | --------------------------------------------------------- |
| `rolling48` (기본) | 매일 D, D+1 48시간 | 앞 24시간만 | **백테스트 마지막 창**에서 `E[마지막] ≥ 기간 시작 에너지` |
| `free`             | 24시간             | 전부        | 없음 (Codex 일별 풀이와 동일)                             |
| `equal_initial`    | 24시간             | 전부        | `E[창 끝] = E[창 시작]`                                   |

- 확정된 24시간 끝 에너지를 다음 창 시작 에너지로 넘긴다. 데이터 끝에서 48시간이 안 되면 남은 시간만 푼다.
- 기간 끝 잔량 제약은 처음 들어 있던 에너지를 팔아 생긴 돈이 ESS 효과로 섞이지 않게 하기 위함이다.
- 종료 조건을 **언제부터** 거는지는 `forecast_rolling.window_terminal` 의 `terminal_mode` 로 정한다.
  `last_day_only`(기존): 구간 마지막 날 24시간에만. `horizon_aware`: 48시간 창이 구간 끝을 포함하는
  마지막 전날부터 창 끝에 같은 조건을 미리 건다 (D+1 잠정 계획이 실험 종료를 모르는 문제 해결). 비교의
  시작·종료 잔량 기준은 같다. 실행 사슬(`execution_rolling`)의 기본은 `horizon_aware`, 기존
  forecast/actual 비교 시나리오는 회귀 비교를 위해 `last_day_only` 를 유지한다.
- 종료 조건이 없는 창 끝에는 `TerminalValue`(소프트 종료)를 선택할 수 있다: 창 끝 잔량 1 MWh 에
  `fraction × η_d × max(0, 창의 예측 판매가치 평균 − 방전 열화비)` 원을 목적함수에 더한다 (계획 시점 정보만).
  평가액은 `terminal_value_krw` 에 따로 적고 `objective_krw` 나 실행 수익에 합산하지 않는다. 2024 하반기
  실측 비교([실행·정산 문서](execution_settlement.md) §5)에서는 v0.1 열화비 아래 ESS 가 거의 움직이지 않아 평가액이
  계획을 바꾸지 못했으므로 기본은 끔.
- 결측으로 제외한 날의 앞뒤는 연속된 것처럼 이어 붙여 푼다(잔량 이월·48시간 창이 제외된 날을 건너뜀).
- 2025-04 `free` 결과는 Codex `ess-v0` 결과와 일치(1,178,887,507.81원, 종료 1.6 MWh)한다.

## 6. 평가·검증

- `evaluation.summarize_backtest`: 판매수익, 열화비, 순수익, 기준 대비 증가액·증가율(ESS 없음, 규칙 계획), 일평균 사이클(방전량 ÷ 사용가능용량 ÷ 일수), 감축량, 기간 시작·끝 에너지.
- `validation.check_plan`: 풀이 상태, 전력균형, SOC 재계산 일치, SOC 범위, 충전·방전 상한, 판매·감축 범위, (판매 상한), 동시 충방전 없음, 종료 에너지, 목적함수 재계산 일치, 롤링 에너지 연속. 위반은 예외 대신 `{item, passed, value}` 목록으로 반환하고 `optimization`이 실패 시 예외를 던진다.
- `validation.check_properties`: MILP ≥ ESS 없음, MILP ≥ 규칙 계획, (크기 여러 개 실행 시) 용량 증가 시 수익 비감소.
- 출력: `data/processed/backtest/<실행ID>/hourly_plan.csv`, `daily_summary.csv`, `baselines_hourly.csv`, `summary.json`, `validation.json`(가정값·한계·데이터 검사·제약 검산 포함). 대시보드 "ESS 운영계획"·"검증" 탭에서 본다.

## 7. 범위 밖 (후속)

REC 실제 단가·발전소별 가중치·발급 기준 확인(현재는 가정값), 용량정산금 연결, 실시간 정산·입찰 편차
페널티, 출력제어 상한 데이터 연결, 실측 백테스트(`vpp.backtest`)의 결측 구간 분리(예측 경로처럼
연속 구간별 재시작), 예측 연결 후 실측 적용 평가(`evaluate_cost`), `schemas.py`·`pipeline.py`·API 연결.
