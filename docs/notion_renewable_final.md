# 재생에너지 발전량 데이터(담당: 박시영)

## 정리 결과 (팀원 전달 파일)

- `renewables_hourly.csv`: 제주 태양광·풍력 시간별 전력거래량. 2021.01~2025.12, 43,824행.
  - `ts`: KST 시간 구간 시작 시각. 재원님 자료와 맞춰 원본 1시를 00:00으로 변환. 제공기관의 공식 시간 정의는 추가 확인 필요.
  - `solar_traded_mwh`, `wind_traded_mwh`: 태양광·풍력 거래량(MWh).
  - 품질 표시 및 원본 파일 출처 포함.
- `jeju_solar_api.csv`: API에서 추출한 제주 태양광 자료. 2021.01.01~2026.08.21, 49,224행.
- `jec_daily_plants.csv`: 제주에너지공사 발전소별 태양광·풍력 일자료. 발전소 명칭 통일, 공사 전체 합계와 개별 발전소 구분.
- 결측·충돌 목록과 품질 보고서도 함께 첨부.

→ 시간별 예측의 메인 Target 후보는 KPX 파일 정리본. API 및 제주에너지공사 자료는 별도로 보관.

## 1. 한국전력거래소_지역별 시간별 태양광 및 풍력 발전량

https://www.data.go.kr/data/15065269/fileData.do

- [x] 공개 파일 및 과거 파일 8개 수집
- [x] 날짜·지역·발전원 표기 통일 및 제주 자료 추출
- [x] 2021~2025년 시간별 정리본 생성, 결측·중복·음수 확인

→ 8개 중 단위가 모호하고 다른 파일로 기간이 포함되는 1개는 병합에서 제외.

→ 태양광은 29개, 풍력은 21개 값이 비어 있음. 시간 키 누락·중복 충돌·음수는 없음.

→ 빈 값은 0으로 바꾸거나 보간하지 않고 그대로 두고, 결측 목록을 별도로 저장.

→ 제주 전체의 순수 발전량이 아니라 전력시장 참여 발전기의 전력거래량 자료. 기존 ESS 충·방전 반영 여부를 고려해야 함.

## 2. 한국전력거래소_지역별 시간별 태양광 발전량 정보

https://www.data.go.kr/data/15103243/openapi.do

- [x] API 활용 신청 및 인증키 설정
- [x] API 제공 전체 이력 수집 후 제주 자료 추출
- [x] 동일 날짜·시간의 기존 파일 자료와 비교

→ 전국 834,214행 중 제주 49,224행 추출. 제주 자료는 2021.01.01~2026.08.21까지 확보.

→ 2024.02.29와 2026.06.01~07은 빠져 있어 총 192시간을 누락 목록에 기록.

→ 2025년 8,760시간은 모두 확보. 기존 파일과 4,947시간의 값이 다르며, 최대 절대 차이는 약 5.015MWh. 해당 시간은 모두 API 값이 더 작음.

→ 2021.01.01~15는 API가 하루 종일 0인데 기존 파일에는 양수가 있어 추가 확인 대상으로 기록.

→ 차이 원인이 확인되지 않아 API로 기존 파일을 덮어쓰거나 결측을 자동으로 채우지 않음. 이 차이는 모델 예측 오차가 아니라 두 데이터 출처 간 차이.

## 4. 제주에너지공사_태양광발전기 전력 정보

https://www.data.go.kr/data/15038930/fileData.do

- [x] 과거 공개 파일 22개 수집
- [x] 발전소 명칭 통일 및 일별 자료 정리
- [x] 누락일·중복·값 충돌 확인

→ 확보한 자료는 일별. 2021년 3분기 92일 자료가 빠져 있음.

→ 발전소별로 자료가 시작되는 시점이 다름. 이전 기간을 발전량 0으로 채우지 않음. 단위 정의도 추가 확인 필요.

## 생각/신경 써야 할 점

- KPX 제주 집계와 제주에너지공사 개별 발전소 자료는 대상과 시간 단위가 달라 서로 빈칸을 채울 수 없음.
- 리나님 기상 자료를 붙일 때 제주 전체 시간별 Target인지, 공사 발전소별 일별 Target인지 먼저 맞춰야 함.
- 발전소별 시간별 예측을 하려면 해당 발전소의 시간별 실적이 추가로 필요. 일자료를 24등분해서 사용하면 실제 시간별 정답이 되지 않음.
- 거래량을 순수 발전량으로 취급하면 기존 ESS 효과를 중복 계산할 수 있음.
- 수집·정제 코드는 작성 완료. 다른 팀원 자료와의 결합 및 모델 연동은 다음 단계. GitHub 업로드는 아직 진행 전.
- 원본·정제 데이터는 파일로 공유하고, 코드·문서는 작업 브랜치에서 PR로 공유 예정. API 키는 공유 파일과 Git에서 제외.
