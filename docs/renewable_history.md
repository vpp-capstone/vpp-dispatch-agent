# 재생에너지 데이터 정리 — 팀 전달본

확인한 팀 페이지: [데이터 정리](https://app.notion.com/p/3f133436f29c8092a33fdef0cd909a4e).
2026-10-10에 브라우저로 읽은 김리나·이재원 담당 항목을 참고했다.
다른 담당자의 진행 현황은 페이지에 적힌 내용이며, 그 원본 파일을 별도로 검증한 것은 아니다.

## 팀 작업과 맞춘 사항

- 시장 담당 정리본처럼 시간별 표, 컬럼 설명, 출처, 결측 정책을 함께 제공한다.
- `ts`는 시장 담당의 **KST 구간 시작 시각** 기준에 맞췄다. 원본 1~24를 00~23시로 변환한다.
- 이 시각 해석은 팀의 결합 규칙에 따른 가정이다. KPX 원본 구간 정의를 공식 문서로 확인한 상태는 아니다. 감사용 파일에 원본 거래일·거래시간을 남긴다.
- 기상 담당이 공사 태양광 5개 단지 위치를 기준으로 준비 중임을 확인했다. 공사 단지별 값은 별도 일별 표로 제공한다.
- 지역 전체 KPX 거래량을 공사 5개 단지의 발전량으로 취급하지 않는다. 지역 전체 Target용 기상 피처는 지역 대표 지점 또는 집계 방법을 별도로 정해야 한다.
- 관측 일사량·풍속은 사후 검증 또는 과거 피처에 쓸 수 있으나, 다음 날 정보를 미리 알 수 있었던 것처럼 학습 입력으로 사용하지 않는다.
- 하루 전 예보를 연결할 때 기상팀이 제시한 전날 11시 마감 기준으로 발행시각을 필터링한다. 이 기준의 제도 근거 검증은 해당 담당 문서를 따른다.

## 실행 순서

저장소 설치 후 루트에서 실행한다. API 키 없이 공개 CSV 원본을 받는다.

```bash
python -m vpp.collect_renewables --since 20210101 --until 20261231
python -m vpp.build_renewable_history --start 2021-01-01 --end 2025-12-31
```

수집 기준 날짜는 **포털 파일 이름의 기준일**이다. 데이터 자체의 날짜 범위는 정제 시 다시 조사한다.
원본은 `data/raw/renewable_sources/`, 결과는 `data/processed/renewable_history/`에 저장한다.
포털이 CAPTCHA를 요구하면 수집을 중단한다. 파일을 다시 사용할 때 체크섬을 확인한다.
위 두 명령은 공개 파일 기반 수집·정제다. KPX 태양광 API는 별도 [수집 명령](kpx_solar_api.md)을 사용한다.
모델·서비스 API 연결은 아직 포함하지 않는다.

### 시간별 컬럼

- `ts`: KST 구간 시작 시각. 시장 정리본과 조인할 후보 키.
- `solar_traded_mwh`, `wind_traded_mwh`: 해당 한 시간의 전력거래량(MWh).
- `solar_quality`, `wind_quality`: `observed`, `missing_value`, `missing_hour`, `conflicting_duplicate`, `negative_review`.
- `solar_source`, `wind_source`: 해당 행의 원본 파일 이름. 동일 키가 여러 파일에 있으면 `|`로 함께 기록.

결측과 충돌은 빈 값으로 유지한다. 0은 실제 관측값이므로 결측과 구분한다.
평균 MW가 필요하면 시간별 MWh를 구간 길이 1h로 나누되, 변환한 컬럼의 단위를 명시한다.
거래량에 기존 ESS 영향이 있으므로 이 표를 순수 재생에너지 발전량으로 간주하여 새 ESS 효과를 중복 계산하면 안 된다.

### 공사 단지별 컬럼

- `date`, `fuel`, `plant_id`: 일자·발전원·통일한 단지 식별자.
- `plant_name`: 해당 원본에 적힌 이름.
- `value_source_unit`, `raw_value`: 수치 변환값과 원본 값.
- `is_reported_total`: 공사 전체 합계인지 표시. 개별 단지와 합계를 함께 더하지 않는다.
- `unit_status`: 단위 미확인이므로 `unverified_daily_source_unit`.
- `quality_flag`, `source_file`: 품질과 출처.

## 원본에서 확인한 사항

### KPX 지역별 시간별 태양광 및 풍력

- 공개 파일 8개 수집. 단위가 모호하고 이후 파일과 중복되는 2021년 기준일 파일 1개는 병합에서 제외했다.
- 나머지 7개로 2021~2025년 43,824시간의 달력을 구성했다.
- 태양광: 관측 43,795개, 빈 값 29개. 풍력: 관측 43,803개, 빈 값 21개.
- 키가 통째로 빠진 시간은 없고, 이번 기간의 중복 충돌·음수는 없다.
- 날짜 열은 `거래일`/`거래일자`, 지역 열은 `지역`/`지역명`으로 달랐다.
- 과거 자료는 태양광·풍력 열이 나란히 있고, 최근 자료는 `연료원`별로 행이 분리돼 있어 긴 표로 통일했다.
- 기준일 이름이 `20230610`인 파일의 실제 내용은 2023년 12월이다. 이름을 보고 6월로 해석하지 않았다.
- 제주 시장 참여 발전기 거래량으로 직접거래·자가용 등은 포함 범위가 다르며 기존 ESS 충·방전이 반영된다.
- KPX 태양광 API도 전체 제공 이력을 수집했다. 제주 49,224행이며 실제 기간은 2021-01-01~2026-08-21이다.
- API에는 2024-02-29와 2026-06-01~07의 192시간이 빠져 있다. API 수집 완료가 결측 없음이라는 뜻은 아니다.
- 파일과 API 비교 결과·연도별 차이는 [실측 검증 보고서](kpx_api_validation_20261010.md)에 있다.

### 제주에너지공사 태양광·풍력

- 각각 공개 과거 파일 22개씩 수집했다. 최신 분기만 봤을 때 드러나지 않았던 오류와 누락이 있었다.
- 태양광에는 2020-12-30·31 행도 포함돼 있다. 해당 원본 날짜를 임의로 2021년으로 바꾸지 않았다.
- 두 발전원 모두 확보한 파일 목록에서 2021-07-01~09-30, 92일이 빠져 있다.
- 2024년 4분기 파일이 9월까지 포함해 3분기 파일과 겹친다. 태양광 171개 날짜·단지 키에서 값이 충돌한다.
- 풍력은 중복된 2022년 2분기 파일 중 1개 날짜·단지 키에서 값이 충돌한다.
- 충돌은 첫 값·나중 값·평균으로 확정하지 않고 빈 값과 충돌 플래그로 남겼다. 각 값은 원본 관측표에서 확인할 수 있다.
- 2023년 1분기 풍력 파일의 날짜 없는 빈 행 2개는 분리했다.
- 2021년 4분기 파일에는 전체 합계 열이 없다. 실제 합계 관측인 것처럼 값을 새로 만들지 않았다.
- 현재까지 확인한 공사 자료는 일별이다. 시간별 Target으로 늘리거나 KPX 시간별 빈칸을 채우지 않는다.
- KPX와 겹치는 날짜는 1,734일이나 집계 대상·단위 차이로 수치 오차를 직접 비교하지 않았다.

## 다음 연결에 필요한 사항

1. 시간별 모델에는 지역 전체 거래량 후보를, 단지 모델에는 일별 공사 관측값을 전달한다. 공사 단지의 **시간별 발전 실적**은 별도 확보가 필요하다.
2. 공사 값의 단위를 확인해야 MWh 변환과 발전량 비교를 진행할 수 있다.
3. KPX API와 파일 간 값 차이의 원인을 확인해야 한다. 실제 인증·전체 수집·비교는 완료했다.
   공식 명세 기반 코드는 `src/vpp/collect_kpx_solar_api.py`, 실행 방법은 [API 문서](kpx_solar_api.md)에 있다.
4. 공식 시간 구간 정의를 확인한 후 KST 결합 규칙을 확정한다.
5. `data.py`의 통합 전달 컬럼과 모델의 예측 대상은 팀 합의 후 연결한다.

현재 상태는 **공개 원본 수집 → 재생에너지 정제 → 전달 파일 생성**까지다.
공통 데이터 로더·기상/시장 조인·모델 학습·서비스 API는 아직 연결되지 않았다.
