# KPX 지역별 시간별 태양광 API

## 공식 명세 확인

2026-10-10 [공공데이터포털 상세 페이지](https://www.data.go.kr/data/15103243/openapi.do)의
내장 Swagger 명세를 직접 확인했다. 응답 필드는 추측한 값이 아니라 해당 명세 기준이다.
단위는 서비스 설명에 기재된 MWh다.

호출 주소:

```text
https://apis.data.go.kr/B552115/PvAmountByLocHr/getPvAmountByLocHr
```

| 구분 | 공식 필드 | 의미 |
| --- | --- | --- |
| 요청 | serviceKey | 공공데이터포털 인증키 |
| 요청 | pageNo / numOfRows | 페이지 번호 / 페이지 크기 |
| 요청 | dataType | json 또는 xml |
| 요청 | tradeYmd | 선택 조건, YYYYMMDD |
| 응답 | tradeYmd | 거래일 |
| 응답 | tradeNo | 거래시간 |
| 응답 | regionNm | 지역 |
| 응답 | amgo | 발전량 수치(MWh) |
| 응답 | rn | 순번 |

`header.resultCode`를 확인하고 `body.items.item` 및 `totalCount`를 읽는다.
JSON 바깥에 `response`가 있는 구조도 지원한다. 게이트웨이 XML 인증 오류도 구분한다.

## 사용자 계정에서 필요한 설정

해당 API의 활용신청 후, 저장소 `.env`에 키를 넣는다. 기존 `.env`의 다른 설정은 유지한다.

```dotenv
DATA_GO_KR_API_KEY=발급받은_인증키
```

시장 담당이 쓰는 `DATA_GO_KR_KEY` 이름도 지원한다. 두 이름을 함께 쓴다면
환경변수/로컬 설정의 우선순위가 달라 혼동하지 않도록 같은 키로 맞춘다.
기상청 키로는 이 서비스를 호출할 수 없다. 실제 키는 채팅·문서·커밋에 넣지 않는다.

## 실행

먼저 파일과 겹치는 하루를 수집한다.

```bash
python -m vpp.collect_kpx_solar_api --date 20250101 --max-calls 3 --compare-file data/processed/renewable_history/renewables_hourly.csv
```

인증·응답이 정상이고 날짜 생략 시 전체 이력 조회가 실제로 지원되는지 확인한 후
전체 수집으로 확장한다.

```bash
python -m vpp.collect_kpx_solar_api --max-calls 90 --compare-file data/processed/renewable_history/renewables_hourly.csv
```

명세에서 `tradeYmd`는 선택 항목이지만, 생략 시 전체 이력의 범위와 페이지 크기 상한은
명시하지 않는다. 기본 10,000행 요청은 수집 효율을 위한 설정이며 실제 허용치는 응답으로 확인해야 한다.
페이지마다 반환된 실제 행 수·페이지 번호·전체 건수·반복 응답을 확인한다.
API에서 전체 이력을 허용하지 않는다면 날짜별 조회 방식으로 수집 범위를 나눠야 한다.

개발계정 트래픽은 포털에 100회로 표시되어 있다. 수집기는 한 번 실행할 때 신규 호출을 최대
90회로 제한한다. 같은 날 다른 스크립트가 쓴 호출 수까지 자동 추적하는 기능은 없다.
호출 한도에 도달하면 `complete=false` 및 종료 코드 3으로 부분 저장을 알린다.
다음 실행은 캐시를 재사용하고 없는 페이지부터 이어 받는다.
정정된 원본을 다시 받으려면 `--refresh`를 사용한다. 새로 받으면 호출량도 다시 사용한다.

## 결과

기본 위치는 `data/raw/kpx_solar_api/`이며 Git 제외 대상이다.

- `jeju_solar_api.csv`: 제주만 추출한 표. 기존 전처리 어댑터에서 읽을 수 있는
  `trade_date,hour_label,region,fuel,traded_energy_mwh` 컬럼.
- `<조회범위>_rows<페이지크기>/page_*.json`: 정상 응답의 원본 캐시.
- `collection_report.json`: 실제 수집 범위·건수·완료 여부·체크섬·비교 결과.
- `api_jeju_observations.csv`: 중복 처리 전 제주 관측값.
- `api_file_comparison.csv`: 파일/ API의 같은 날짜·시간별 차이.
- `comparison_by_year.csv`: 연도별 비교 가능 시간·값 차이·최대 절대 차이.
- `api_missing_hours.csv`: API에서 빠진 거래일·거래시간 키.
- `api_zero_day_review.csv`: API가 하루 종일 0인데 파일에는 양수 관측이 있는 검토 대상 일자.

조회 범위를 바꿔 실행하면 최상위 CSV·보고서는 마지막 실행 결과로 갱신된다.
날짜별 원본 페이지는 각 범위 폴더에 따로 남는다. 하루 수집 결과를 전체 수집으로 표시하지 않는다.
`--workers 1`이 기본이며, 독립된 페이지를 동시에 받으려면 최대 `--workers 8`을 지정한다.
동시 수집도 같은 호출 예산을 공유한다. 중간 전송 오류가 나면 정상 수신한 캐시를 남기고
부분 수집 상태를 기록한다. 호출 한도와 서버 상태를 확인한 후 이어 받는다.

API와 파일 값이 다르면 수정정산·집계 범위·ESS 반영 등을 먼저 확인한다.
비교만 수행하며 기존 Target을 자동 교체하거나 결측을 채우지 않는다.

## 현재 상태

- 공식 주소·요청 파라미터·응답 필드 확인 완료.
- 로컬 키 로딩·페이지 수집·캐시·제주 추출·파일 비교 코드 작성 완료.
- 실제 인증 호출 성공. `tradeYmd=20250101` 조회에서 전국 408행, 제주 24행을 받았다.
- 해당 날짜의 파일과 비교 가능한 제주 24시간 중 12시간의 값이 달랐다.
  최대 절대 차이는 2.427676MWh다. 이 차이는 예측 오차가 아니라 두 실측 소스의 차이다.
- 날짜 조건 없는 조회도 성공했으며 API가 제공하는 전체 834,214행을 84페이지로 수집 완료했다.
- 제주 태양광은 2021-01-01~2026-08-21의 49,224행이다. 중복·빈 수치·음수는 없지만
  날짜 범위의 예상 49,416시간보다 192시간이 부족하다.
- 누락: 2024-02-29 하루와 2026-06-01~07 일주일. API 전체 응답 다운로드 완료와
  시간축 결측이 없다는 의미를 구분한다.
- 2021~2025년 파일과 비교 가능한 43,771시간 중 32,395시간이 다르다.
  자세한 연도별 수치와 주의사항은 [실측 검증 보고서](kpx_api_validation_20261010.md)에 있다.
- 단위 테스트는 추가하거나 실행하지 않았다.

실제 호출을 마친 뒤 `collection_report.json`의 수집 범위와 비교 수치로 이 상태를 갱신한다.
