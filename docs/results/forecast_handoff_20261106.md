## 입력 연결 검사

처음에는 파일 전체를 엄격한 48시간 검사에 넣었고 연도 경계의 일부 창이 불완전하여 차단됐다.
검증용 파일은 실제 정답을 가진 행만 담고 있어, 연도 경계 또는 발전소 정답 누락 때문에
한 계획일의 48시간·발전소 집합이 완성되지 않을 수 있다. 이를 파일 전체 오류로 해석하지 않는다.

불완전한 계획일은 창 전체를 명시적으로 제외하고, 보간/0 채우기 없이 다시 연결했다.

| 항목 | 결과 |
|---|---:|
| 태양광 완전한 48시간 창 / 불완전 창 | 365 / 2 |
| 풍력 완전한 48시간 창 / 불완전 창 | 338 / 29 |
| SMP 완전한 48시간 창 / 불완전 창 | 579 / 0 |
| 세 자료의 공통 완전 창 | 188 |
| 공통 입력 행 수 | 9,024 |
| 그 중 실측 대상시각을 모두 확보한 창 | 188 |

계획일 범위는 2024-05-31~2024-12-29이며 중간에 제외된 날짜가 있다.
대상시간은 각 계획일의 다음 날부터 48시간이다.
9,024행은 서로 겹치는 48시간 창을 포함하므로 서로 다른 9,024시간을 뜻하지 않는다.

- 정확한 태양광 18개·풍력 3개 ID, 중복, 발전량 유한성·음수·설비용량 상한 검사.
- 각 모듈의 발행시각과 lead_hour 검증, KST 대상시각 48시간 연속성 검사.
- kWh→MWh 및 원/kWh→원/MWh 단위 변환 검사. 0원/음수 SMP는 보존.
- 발행시각이 다른 GFS와 SMP는 계획일+대상시각으로 결합.
- 실제 정답 generation_kwh/smp_actual은 예측 입력에서 제외.
- 선택된 자료를 기존 align_forecasts 검증 함수에 다시 통과시켰다.

## 아직 검증하지 않은 내용

- 원천 예보의 실제 공개 지연과 모델 학습/튜닝 전체의 시점 누수 여부.
- 규리님 통합 구현의 입력 값과 이번 출력 값이 동일한지.
- 예측 오차 발생 후의 ESS 실행 가능성과 실현 수익.
- 2025년 최종 평가용 발전량 예측. 이번에 받은 두 발전량 파일은 2024년 검증용이다.

따라서 이번 결과를 실제 수익 개선이나 2025년 최종 모델 성능으로 해석하지 않는다.
이전 실측 전용 보고서에서 '예측 파일 미확보'로 남았던 사항은 이번 확보/검사로 갱신한다.

## 공유 파일의 의미

- complete_forecast_windows.csv: 완전한 공통 48시간 입력. planning_date별로 선택해서 사용한다.
  계획일을 무시하고 ts만으로 연결하면 겹치는 예측을 중복 처리하므로 주의한다.
- incomplete_forecast_windows.csv: 모듈별로 불완전해 제외한 계획일과 사유.
- drive_forecast_inventory.json: 파일 식별, 소스별 범위, 공통에서 빠진 날짜, 검사 한계.

같은 Drive 폴더를 확인한 범위에서 필요한 세 파일은 모두 있었으므로 다시 요청할 필요가 없다.
2025년 최종 평가 자료의 존재 여부는 별도로 확인해야 한다.

## 정식 명령 재현 및 테스트

[실행 문서](../data_handoff_audit.md)의 `python -m vpp.handoff_audit` 명령에
실제 예측 파일 3개와 `--incomplete-windows exclude`를 지정해 다음을 재현했다.

- `INPUT_ALIGNMENT_CHECKED`, 공통 창 188개, 출력 9,024행.
- 대상 실측이 없는 예측 행 0개, 실측 비교가 가능한 창 188개.
- 앞서 별도 점검 스크립트로 생성한 입력과 계획일·시각·발전량·가격·간격이 동일함을 대조.
- 전체 테스트 **80 passed** (기존 55개 + 이 모듈의 25개).
- 새 모듈·테스트 `ruff check` 통과. 기존 SMP 코드의 pandas 경고 16개는 남아 있음.

기본 reject 모드는 누락 창을 오류로 처리한다. exclude를 명시한 경우만 누락 창 전체를
기록 후 제외하며, 중복·음수 발전량·단위 오류·잘못된 발행시각·미등록 발전소는 여전히 오류다.
실패/미완료 재실행 시 이전 성공 예측 출력이 남지 않는 것도 CLI 테스트로 확인했다.
