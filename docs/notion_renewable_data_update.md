# 재생에너지 발전량 데이터(담당: 박시영)

## 정리 결과 (팀원 전달 파일)

- `renewables_hourly.csv`: 제주 태양광·풍력 시간별 전력거래량 (2021.01~2025.12, 43,824행)
  - `ts`: KST 구간 시작 시각. 재원님 정리본의 기준에 맞춰 원본 1시를 00:00으로 변환했습니다. 제공기관의 공식 구간 정의는 추가 확인이 필요합니다.
  - `solar_traded_mwh`, `wind_traded_mwh`: 태양광·풍력 거래량(MWh)
  - `solar_quality`, `wind_quality`: 관측/결측 등 품질 표시
  - `solar_source`, `wind_source`: 원본 파일 출처
- `jec_daily_plants.csv`: 제주에너지공사 단지별 일별 값. 단지 이름을 통일했고, 공사 전체 합계는 별도로 구분했습니다. 단위는 확인 전이라 원래 수치를 유지했습니다.
- `renewable_hourly_issues.csv`, `jec_conflict_keys.csv`: 결측 및 파일 간 값 충돌 목록
- `history_quality.json`: 원본별 출처·기간·체크섬과 품질 점검 결과

## 한국전력거래소_지역별 시간별 태양광 및 풍력 발전량

- [x] 공개 파일 및 과거 파일 8개 수집
- [x] 파일마다 다른 날짜·지역·발전원 표기를 정리하여 제주 자료로 병합
- [x] 2021~2025년 시간별 표와 품질 보고서 생성

→ 8개 중 단위가 모호하고 다른 파일로 기간이 포함되는 과거 파일 1개는 병합에서 제외했습니다.

→ 태양광은 43,795개 관측·29개 빈 값, 풍력은 43,803개 관측·21개 빈 값입니다. 이번 기간에 시간 키 누락·중복 충돌·음수는 없었습니다.

→ 빈 값은 0으로 바꾸거나 보간하지 않았습니다. 실제 0인 값과 구분해서 두었습니다.

→ 파일 이름은 `20230610`인데 실제 내용은 2023년 12월인 자료가 있어, 실제 거래일을 기준으로 병합했습니다.

→ 이 자료는 제주 전체 발전량이 아니라 전력시장 참여 발전기의 **전력거래량**이며, 기존 ESS 충·방전도 반영되어 있습니다.

## 한국전력거래소_지역별 시간별 태양광 발전량 정보 API

- [x] 공식 Swagger에서 호출 주소·요청 조건·응답 필드 확인
- [x] 인증키 로딩·캐시·제주 추출·기존 파일 비교 코드 작성
- [x] 해당 API 인증키 및 실제 응답 확보
- [x] API가 제공하는 전체 이력 834,214행 수집 및 제주 49,224행 추출
- [x] 2025년 전체를 같은 날짜·시간의 파일 자료와 비교

→ API에서도 2025년 제주 8,760시간을 모두 확보했습니다. 파일과 4,947시간의 값이 다르며, 최대 절대 차이는 5.014801MWh입니다. 차이가 난 시간은 모두 API 값이 더 작았습니다.

→ 원인이 확인되지 않아 API를 정정본으로 간주하거나 파일 결측에 자동으로 채워 넣지 않았습니다. 파일과 API를 별도 출처로 보관합니다. 이는 모델 예측 오차가 아니라 두 실측 소스의 차이입니다.

→ 공식 응답 `tradeYmd`, `tradeNo`, `regionNm`, `amgo`를 기존 정리 형식으로 변환합니다. 실행 방법은 레포 `docs/kpx_solar_api.md`에 정리했습니다.

→ API 제주 자료는 2021.01.01~2026.08.21입니다. 2024.02.29와 2026.06.01~07은 빠져 있어 192시간을 결측 목록에 기록했습니다.

→ 2021년 1월 1~15일은 API가 하루 종일 0인데 파일에는 양수가 있어 추가 검토 대상으로 남겼습니다. 기존 파일을 메인 후보로 유지합니다.

## 제주에너지공사_풍력·태양광발전기 전력 정보

- [x] 과거 공개 파일 태양광 22개·풍력 22개 수집
- [x] 단지별 이름 통일 및 일별 정리본 생성
- [x] 누락일·중복·값 충돌 점검

→ 확보된 자료는 시간별이 아니라 **일별**입니다. 두 발전원 모두 2021년 3분기 92일 자료가 빠져 있습니다.

→ 중복 파일에서 태양광 171개·풍력 1개의 날짜·단지 키가 서로 다른 값을 갖고 있습니다. 임의로 하나를 정하지 않고 충돌 목록과 원본 값을 따로 남겼습니다.

→ 공사 단지별 자료와 KPX 제주 집계 자료는 대상이 달라 서로 빈칸을 채우지 않았습니다.

## 생각/신경 써야 할 점

- 리나님이 공사 단지 위치를 기준으로 기상을 준비 중인 내용을 확인했습니다. 공사 일별 Target과 지역 전체 KPX 시간별 Target은 구분해서 붙여야 합니다.
- 공사 단지의 시간별 예측을 하려면 해당 단지의 시간별 발전 실적을 추가로 확보해야 합니다. 일별 값을 24등분하면 실제 시간별 정답이 되지 않습니다.
- 단위·시간 구간 정의가 확정되면 기상/시장 자료와 연결할 수 있습니다.
- 기존 ESS가 반영된 거래량을 순수 발전량으로 취급하면 ESS 효과를 중복 계산할 수 있습니다.
- 원본·정제 CSV는 Git에 올리지 않고 공유하고, 수집·정제 코드와 문서는 레포에 올리는 방식입니다.
